# ResearchForge Coding Harness V1

## 定位

V1 面向研发团队，解决一个明确问题：从真实代码仓库中的缺陷任务出发，经过隔离执行、模型补丁、测试验证和人工审批，产出可审查的代码变更或 Pull Request。

Research、Notebook、训练、在线 RL、企业身份和跨区域灾备保留为扩展能力，不作为 V1 发布门槛，也不继续扩展其功能面。

## V1 主链路

```text
真实仓库/任务 -> PRECHECK -> 隔离工作区 -> 千问模型 -> 受控工具调用
-> 补丁 -> 测试 -> Critic -> Trace/成本 -> 人工审批 -> PR 草稿
```

## V1 范围

必须稳定：

- GitHub 或本地 Git 仓库接入，仓库凭据不进入任务记录。
- Docker 或 Kubernetes 沙箱，沙箱默认无网络、只挂载当前任务工作区。
- OpenAI-compatible 模型网关，首个真实供应商为 Qwen/DashScope。
- PRECHECK、补丁、测试、有限重试、Critic、审计和完整 Trace。
- Golden Task 批量评测、成本统计、失败分类和 Release Gate。
- 人工审批后生成分支和草稿 Pull Request。
- 中文工作台展示任务、运行、日志、Diff、测试和评测结果。

V1 暂不承诺：

- 自动合并生产分支。
- 自动在线强化学习或自动更新模型权重。
- 多区域自动故障切换和无人工确认的 DNS 提升。
- Research 工作台的完整科研闭环。

## 发布门禁

首轮试运行使用 10 个 `coding_golden_v1` 任务：

| 指标 | 试运行要求 | 说明 |
| --- | ---: | --- |
| Golden Task 配置有效率 | 100% | 每个任务必须有执行配置和成功标准 |
| 真实模型调用 | 100% | provider 不能是 `mock` |
| Mock 回退次数 | 0 | Qwen 不可用时必须失败，不能伪装成功 |
| 策略违规 | 0 | 不得越过路径、命令和审批策略 |
| 成功率 | >= 70% | 作为首轮可用性基线；达到 80% 才考虑扩大试用 |
| Trace 完整度 | >= 95% | 必须能还原关键步骤和工具调用 |
| 测试文件修改 | 0 | 除非任务明确允许 |
| 成本与耗时 | 必须记录 | 首轮先建立基线，不预设供应商无关的固定阈值 |

## 真实验收顺序

1. 在模型网关登记 Qwen `openai_compatible` 配置，并执行连通性检查。
2. 用一项 Golden Task 做单任务 Smoke Test，确认没有 Mock 回退。
3. 执行十任务批量验收，保存 JSON 和 Markdown 报告。
4. 选两个可公开复现的真实仓库执行端到端修复，人工检查 Diff 和测试日志。
5. 接入一个测试 GitHub 仓库，验证分支、审批、草稿 PR 和回滚路径。
6. 根据失败分类修复 Runtime、策略或提示词，再重复十任务验收。

## 成功定义

V1 完成不等于“所有平台模块都已生产化”。V1 完成的定义是：上述主链路可重复运行，真实模型结果可解释，失败不会越过安全边界，评测结果能支持是否发布的决定。
